Your turn.

Here is how to practice what you just heard.

First, build the synthetic database, once, from the root of the course repository. The command is R script, then data slash build r t b sample dot R. It writes the database, and it also writes the reference results for this module into a folder called expected.

Second, open the exercise file in the module six folder. It has four blocks, one per table, in the same order as this lesson. Each block tells you the table to create, the columns it should have, and the rules in words. Below each one there is a line that says, your query here. The reference answers are at the bottom of the file, commented out, so try each block cold before you scroll down.

Third, grade your work. From the repository root, run python, then module six slash check dot p y, then the name of your file. The grader copies the database to a scratch file, runs your whole file the way the real pipeline does, and prints one line per block: pass, or the first difference it found. A blank file fails all four blocks. The reference solution passes all four. If block one fails, the later blocks will usually fail too, because they read from your all table. Fix them in order.

A few mistakes to try on purpose, because the grader catches each one, and seeing the message teaches more than reading about it. Move the date test of the left join from the on clause into the where clause, and watch six lists vanish. Remove a coalesce from the industry block, and watch the Sports row turn null. Drop the parentheses around the or in block one, and count the rows that sneak through. Forget the list of skipped dates in block four, and see three extra rows.

Fourth, take the walking quiz. It reads each question aloud and adapts as you go. Some questions say, look at the code on the screen. For those, glance at the phone. The code is never read aloud. You can tap an answer while the question is still being read, and tap the question to hear it again.

And last, when the synthetic version feels easy, read the real file and its notes in the opa prop forty repository, in the B S Z analysis folder, under s q l. You will recognise every block. The notes there also document how the real run was checked against the authors' sheets, including the two vintage gaps from the previous section.

That is the module. Four blocks: who counts, the year-end lists, the industry table, and the daily totals. Three habits: store tables, keep the file to pure SQL, and think about null before you think about anything else. And one way of working: when your numbers disagree with someone else's, name the difference before you call it a mistake.
